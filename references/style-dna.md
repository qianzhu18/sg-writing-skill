# Style DNA：克制冰山叙事

这份参考文档把 `sg-writing-skill` 的写法拆成可观察的结构。它用于在触发 Skill 后做判断，不是要求每篇文章机械套用全部特征。

## 一、五个核心维度

| 维度 | 可观察信号 | 使用方式 | 失控信号 |
|---|---|---|---|
| 句子节奏 | 叙事多用短到中句，情绪高点更短 | 关键动作单独成行；过程细节可放慢 | 全文每句同长，像提纲或流水账 |
| 数字锚点 | 时间、金额、数量、距离等可测量细节 | 每三百至五百字选一至三个；短文更少 | 每句话报数、数字无来源或无作用 |
| 冰山表达 | 情绪由行为、物件、身体反应显现 | 为核心情绪选择一个可重复载体 | 用“我很X”解释完，再补装饰细节 |
| 事实并置 | 两个事实靠近后产生落差 | 同日、同物、同金额或同一空间形成对比 | 为了反差拼接无关事实 |
| 克制收束 | 场景结束时留下一句短判断或状态 | 在真正完成的段落收住，不强求每段都有 | 结尾变成鸡汤、格言或作者解说 |

## 二、建议的句长分布

不要把比例当作硬性指标。可以用下面的趋势做自检：

- 场景锚定：一至两句短句，让读者迅速进入现场。
- 行为推进：以短句和中句为主，按动作先后写清楚过程。
- 情绪峰值：缩短，留出空行或停顿，删去心理解释。
- 回望与收束：恢复平静，使用一个具体状态代替总结。

短句不是“每句都断开”。如果连续短句没有新的动作、事实或视角变化，应该合并；如果一段长句只是为了表达情绪，应该拆开。

## 三、数字锚点的选择

### 优先级

1. 用户已提供、且与事件直接相关的数字。
2. 场景天然产生的测量值，例如车次、门牌、等待时长、账单金额。
3. 创作中允许虚构的数字，但要保持内部一致，并避免伪装成事实。

### 选择标准

数字至少满足下面一项：

- 让抽象关系变得可见；
- 与另一个数字形成反差；
- 让重复动作有时间或数量的重量；
- 改变读者对场景规模的判断。

若只为“风格像”而加入数字，删掉它。缺少有效数字时，优先写物件的尺寸、位置、磨损、声音或动作顺序。

## 四、情绪载体设计

不要直接套用固定的“情绪→道具”词典。通过以下问题生成更贴合文本的载体：

1. 这个人会反复做什么，且自己不认为那是表达？
2. 哪件普通物品因为关系变化而改变了位置、用途或状态？
3. 身体的哪个微小反应与人物口头表达不一致？
4. 载体在开头、中段、结尾是否发生了变化？

好的载体会推进事件，而不是只作装饰。例如，反复检查门锁可以在第一次表现习惯，在结尾表现无法确认的事已经发生变化。

## 五、段落骨架

```text
可见锚点
→ 一个具体动作
→ 动作中的偏差或阻力
→ 事实并置 / 物件变化
→ 不解释的短收束
```

不是每个段落都需要完整五步。对话或转场可以只有一至两步；核心场景才值得慢写。

## 六、语言与格式

- 默认第一人称，但改写时保留原文视角。
- 中文散文默认使用中文数字；技术、法律、财务和原文格式优先保证准确与可读。
- 默认不用标题、小标题和解释性导语；用户指定的格式优先。
- 对话默认不用引号，使用“他说，……”的叙述式写法；出版规范、剧本或用户原文要求例外。
- 让标点服务停顿，不用感叹号或省略号代替情绪。引用、对白和用户指定格式可保留。

## 七、常见失败与修复

| 失败 | 症状 | 修复 |
|---|---|---|
| 数字堆砌 | 一段里连续出现很多时间、金额和数量 | 只留能改变理解的数字，其余换成动作 |
| 伪克制 | 句子很短，但每句都在宣布情绪 | 删除判断，补可观察细节 |
| 伪哲学 | 结尾像社交媒体金句 | 以物件状态、动作结果或一个事实收尾 |
| 过度留白 | 读者不知道谁做了什么 | 补足必要的主语、动作和时间关系 |
| 事实漂移 | 改写后日期、金额、人物关系变化 | 回到事实表逐项核对 |
| 风格复制 | 出现参考文本的原句或独特数字组合 | 重写场景、人物、数字和意象，只保留高层机制 |

## 八、同案多视角

多视角不是把同一篇文章改成不同人称，而是让同一组事件经过不同角色的权限、利益和注意力重新显影。先锁定共同底稿，再分别决定角色能看到什么、不能确认什么，以及哪个物件承载他的情绪。

同一场电话在伴侣那里可以是一次被迫作答，在服务人员那里只是交接记录，在助手那里是一项待确认的安排；事实不必增加，意义会因为观察位置变化。涉及现实人物时，使用“角色位置 + 文学化虚构”标签，避免把虚构独白包装成真人观点。完整案例见 `references/multi-perspective-case-study.md`。

长篇多视角还需要两个额外约束：一是篇幅响应，用户要求“与原文差不多长”时先测量源文本，默认控制在 `85%–120%`；二是交叉锚点，每个视角至少与其他视角共享三个事件或物件。只有角色之间互相照亮，同一件事才会越写越厚，而不是被拆成几篇无关短文。
